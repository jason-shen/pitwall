The loop

Brief. Build. Review. Ship.

01

Write the brief.

Start from a template made for agent work: feature, bug, refactor, UI polish, spike. Type the ask in your own words, then hit ✦ Finish with AI. Claude reads your code and fills in the problem, the files, the steps and the open questions while you watch it write.

04

Review like a lead, not a typist.

Read the agent's diff against where it started. Comment on any line, then send every comment back as one message for its next turn. Throw away a hunk you don't want. Every step it took is a snapshot you can revert to.

Safety

Guardrails that only tighten.

pitwall never quietly allows a command on its own reading of the shell. It denies what your rules deny, queues what needs a look, and leaves the rest to the agent's own prompt.

mutating add-metrics wants to run npm install --save-dev jest && cargo test viewApprove ⌘⇧YReject ⌘⇧R
✕ refusedcargo test && rm -rf ~each part judged on its own, strictest answer wins

Deny rules hold everywhere

Behind sudo, FOO=1, git -C dir, and inside bash -c '…'.

A snapshot before every step

A shadow-git timeline for each agent. Diff any step, revert to it, undo the revert.

Agents together

Agents that talk to each other.

Every pitwall terminal has the pitwall command on its PATH. Agents list, message, wait on and read one another, so a builder can hand off to a reviewer without you in the middle.

builder
$ pitwall agents
  ● builder    working   ~/code/app
  ● reviewer   idle      ~/code/app
$ pitwall tell reviewer "check the login fix, then tell me"
  sent to reviewer
$ pitwall wait reviewer
$ pitwall read reviewer -n 4
  [message from agent reviewer] Looks right. Two small
  notes on the cookie flags, left as comments.

Your ssh, your config

Sessions run your own ssh, so ProxyJump and your agent work. Hosts in ~/.ssh/config show up on their own; add others in the app.

One command, every box

Run… sends a command to a group and shows each server's exit code and output. Anything that changes things asks first.

Agents on servers too

A claude running on a server is read off its screen and listed as build box · claude, marked remote.

Underneath

And it's a real terminal.

Drawn on the GPU. Agents run in their own TUIs, with your shells, vim and lazygit tiled beside them.

Close the window. Nothing stops.

A background daemon owns every terminal. Quit the app and your agents keep working. Restart the machine and they come back in their folders and pick up their sessions.

Tabs and tiles

Split, drag, swap and resize cards. Broadcast typing to all of them.

Git built in

lazygit's layout and keys: stage hunks, commit, check out, all in the window.

Your editor, or ours

A built-in editor that reloads live, or nvim, helix, VS Code, Cursor, Zed.

Scrollback that survives

Restarts keep it. Narrow a card and the text rewraps instead of getting cut.

Keys that work

kitty keyboard protocol, so Shift+Return is a newline in Claude Code and Codex.

Every language

IME for Chinese, Japanese and Korean. UI in seven languages.

API keys, locked away

Tokens sealed with AES-256-GCM behind their own password. Reveal or copy asks every time; the clipboard clears itself.
